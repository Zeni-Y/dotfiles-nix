# markdown / HTML / メディアプレビュー (`hiraku`)

リモート (このマシン) にある markdown / HTML / 画像 / PDF / 音声を、手元のブラウザ
(Chrome など) で見るためのコマンド。実装は `home/cli/hiraku.nix` と
`home/cli/hiraku/` (サーバー本体と画面)。

## 1. 全体像

```
リモート                                            ローカル
──────────────────────────────────────              ────────────────────────
docs/  ──┐
site/  ──┤                                          http://localhost:4649/
a.wav  ──┴─▶ hiraku (フォアグラウンドで常駐)                    ▲
              ├ ファイルツリー + プレビューの 2 ペイン画面      │
              ├ md はリクエストのたびに pandoc で HTML 化       │
              ├ それ以外は実体をそのまま配信                    │
              └ 変更を監視して SSE でブラウザに通知     ── SSH トンネル ──┘
             (python3 の HTTP サーバー、127.0.0.1:4649)
```

- 変換も配信もリモートで完結する (pandoc + python3、完全オフライン)。
- **`hiraku` を動かしている間だけ見える**。Ctrl-C で終了するとブラウザからも
  見えなくなり、ディスクには何も残らない (→ [4 章](#4-動いている間だけ見える))。
- HTTP サーバーは **127.0.0.1 にしか束縛しない**。LAN には公開されず、
  届く経路は SSH の LocalForward だけ。

## 2. 事前準備 (ローカル側、初回のみ)

ローカルマシンの `~/.ssh/config` で、このリモートのエントリにポート転送を足す:

```
Host <このリモート>
    LocalForward 4649 localhost:4649
```

接続済みのセッションには効かないので、設定後に SSH を張り直す。
その場しのぎなら `ssh -L 4649:localhost:4649 <host>` でもよい。

## 3. 使い方

```bash
hiraku docs/                # ディレクトリ: ツリーから選んで右ペインで読む
hiraku README.md            # ファイル: その親ディレクトリが対象になり、README.md を開いた状態で始まる
hiraku site/index.html      # HTML はそのまま配信 (相対パスの画像・CSS も生きる)
hiraku shot.png             # 画像: 拡大・縮小できるビューアで開く (→ 3.4 節)。PDF はブラウザ任せ
hiraku take1.wav            # 音声: 波形付きプレーヤーで開く (→ 3.3 節)
hiraku docs/ ~/notes        # 複数指定すると 1 つのサーバーでまとめて配信する
hiraku -p 4650 docs/        # ポートを変える (LocalForward 側も合わせること)
```

表示された URL をローカルのブラウザで開く。**終わるときは Ctrl-C**。

### 3.1 画面

```
┌──────────────┬──────────────────────────────┐
│ docs         │                              │
│ [すべて   ▾] │                              │
│ ▾ git        │       プレビュー             │
│    worktree… │       (iframe)               │
│ ▸ nix        │                              │
│   README.md  │                              │
└──────────────┴──────────────────────────────┘
                ↑ 境界をドラッグして幅を変えられる
```

- **ツリーは 1 階層ずつ開く**。最初はディレクトリが畳まれた状態で、クリックすると
  その中身が出る (もう一度クリックで畳む)。配下を再帰的に全部並べないので、
  大きなディレクトリを渡しても最初の表示が軽い。開閉の状態は記憶する。
- **拡張子で絞り込める**。左上のプルダウンで「すべて / markdown / HTML / 画像 /
  PDF / 音声」を切り替える。選んだ種類のファイルを 1 つも持たないディレクトリは
  ツリーから消える。
- **境界のドラッグでツリーの幅を変えられる**。幅は次回以降も引き継ぐ。
- **ファイルを変更するとすぐ反映される**。サーバーが変更を検知してブラウザに
  伝え、**開いているファイルだけ**を読み込み直す (スクロール位置は保つ)。
  ファイルが増減したときはツリーも作り直す。

### 3.2 対応形式

| 種類 | 拡張子 | 表示方法 |
| --- | --- | --- |
| markdown | `.md` `.markdown` | pandoc で HTML に変換 (アクセスのたびに変換するので常に最新) |
| HTML | `.html` `.htm` | そのまま配信 (相対パスの画像・CSS も生きる) |
| 画像 | `.png` `.jpg` `.jpeg` `.gif` `.svg` `.webp` `.avif` `.bmp` `.ico` | 拡大・縮小できるビューア (→ 3.4 節) |
| PDF | `.pdf` | そのまま配信 (ブラウザ内蔵の PDF ビューア) |
| 音声 | `.mp3` `.wav` `.ogg` `.oga` `.flac` `.m4a` `.aac` `.opus` | 波形付きプレーヤー (→ 3.3 節) |

これ以外の拡張子はツリーに出ない。隠しディレクトリ (`.git` など) と
`node_modules` も除外する。

### 3.3 音声プレーヤー

音声を選ぶと `/player.html?src=...` が右ペインで開く。できること:

- **波形表示**: ステレオなら L (上・青) / R (下・緑) の 2 段。ブラウザがファイル全体を
  デコードして描くため、長尺ファイルは表示までに数秒かかる。
- **タイムラインの移動**: 波形のクリック / ドラッグでシーク。`←` / `→` で 5 秒移動、
  `Space` で再生 / 停止。下の標準プレーヤーのシークバーも使える。
- **チャンネルの切り分け**: 「L のみ」「R のみ」を選ぶと、そのチャンネルだけが
  **両耳に**流れる (片耳だけ鳴らすと聴き比べづらいため)。聴いていない側の波形は
  薄く表示され、モノラルではボタン自体が出ない。

再生できる形式はブラウザ依存 (Chrome なら上の表の拡張子はすべて可)。波形の生成に
失敗しても、標準プレーヤーでの再生は試せる。

### 3.4 画像ビューア

画像を選ぶと `/image.html?src=...` が右ペインで開く。操作:

| 操作 | 動き |
| --- | --- |
| 左クリック | カーソルの位置を中心に 1.5 倍に拡大 |
| Ctrl + 左クリック | 同じく 1/1.5 倍に縮小 |
| 左クリック長押し (かドラッグ) | 掴んで移動 (grab) |
| 右上の倍率をクリック | 全体表示に戻す |

- **倍率は常に右上に出る** (`100%` = 画像の実ピクセル等倍)。その左には元の
  ピクセル寸法を出す。範囲は 5%〜3200%。
- **最初は全体表示**。ペインに収まらない画像は縮めて全体を出し、収まる画像は
  等倍のまま出す (小さい画像を引き伸ばしてぼかさないため)。
- **拡大・縮小はカーソルの下の点を固定する**。見ている場所が画面外へ逃げない。
- **倍率と位置は保つ**。画像を作り直して保存すると同じ場所を拡大したまま
  差し替わるので、生成し直した図を見比べられる (ページを開き直すと全体表示に戻る)。
- 透過部分は市松模様で示す。

## 4. 動いている間だけ見える

`hiraku` は**フォアグラウンドで動き続けるプロセス**で、それ自体が HTTP サーバー。

- **Ctrl-C で終わる**。プレビューもそこで見えなくなる。変換結果をディスクに
  残さないので、後片付けも要らない。
- **ずっと見たいならバックグラウンドに回す**。
  ```fish
  hiraku docs/ &; disown        # fish
  ```
  ```bash
  hiraku docs/ & disown         # bash
  ```
  herdr のペインで動かしたままデタッチしても同じこと (ペインが生きている間は見える)。
- **同じポートは 1 プロセスしか使えない**。2 つ目を起動したいときは対象を
  まとめて 1 回で渡すか、`-p` で別のポートにする (その場合ローカル側の
  LocalForward も足す)。

## 5. 設計判断

- **1 回の起動 = 1 プロセス = 1 ポート**。以前は「常駐サーバー 1 個 + ファイルごとの
  登録」という作りで、`~/.cache/hiraku` に変換結果と登録簿を貯めていた。これをやめたのは
  (1) Ctrl-C しても常駐サーバーが残り、何が見えているのか分からなくなる
  (2) 見た覚えのないファイルがキャッシュに残り続ける、の 2 点。
  複数の対象を同時に見たい場合は**引数を並べる**ことで 1 ポートのまま扱えるので、
  LocalForward が 1 行で済むという元の利点は保てる。
- **サーバーを切り離さない (setsid しない)**。旧版は entr の Ctrl-C でサーバーまで
  道連れになるのを避けるため `setsid` で別セッションに逃がしていたが、その結果
  「Ctrl-C しても止まらない」ものが残った。いまは監視も配信も同じプロセスなので、
  素直に SIGINT で終わればよい。シェル側も `exec python3` で置き換えて、
  シグナルと終了ステータスを中継する層を無くしている。
- **md は事前生成せず、リクエストのたびに pandoc に通す**。ディスクに中間生成物を
  持たない代わりに、開いた瞬間の内容が必ず出る。entr での差分再変換も不要になった。
- **`--embed-resources` をやめた**。ページ自身が `/view/<対象>/<ディレクトリ>/` という
  URL で配信されるので、相対パスの画像・CSS・他の md へのリンクはブラウザが同じ
  サーバーに取りに来て解決できる。埋め込みより速く、リンクを辿れる。
- **変更の検知は mtime の定期スキャン (0.7 秒)**。inotify を使わないのは依存を
  増やさないため。うっかり巨大なディレクトリを渡したときのために 1 周で見る
  エントリ数に上限を置いている。
- **通知は SSE (Server-Sent Events)**。ブラウザ標準の `EventSource` だけで済み、
  WebSocket のライブラリを持ち込まずに「変更されたファイル名」を送れる。
  旧版の `-r 秒` (meta refresh による定期リロード) は要らなくなったので廃止した。
- **ツリーは 1 階層ずつ (遅延展開)**。全ファイルを 1 枚の HTML に書き出す旧版は、
  対象が大きいと最初の表示が重く、目的のファイルも探しづらかった。
- **レンダラは pandoc (gfm 入力)**。grip は GitHub API 依存 (オフライン不可・レート制限)
  なので不採用。
- **ポート既定値は 4649**。well-known / ephemeral を避けた覚えやすい値で、
  ローカル側の LocalForward を固定で書いておける。
- **音声の波形とチャンネル切替はブラウザ側 (Web Audio API) でやる**。サーバー側で
  波形画像を作る案 (ffmpeg / audiowaveform) はリモートの依存が増えるうえ、クリックでの
  シークやチャンネル切替のような対話ができないので不採用。プレーヤーは全プレビュー
  共通の静的ページ `/player.html` で、`?src=` で対象を受けるため、音声ファイルごとに
  ページを生成しない。
- **画像はブラウザのネイティブ表示に任せない**。素の表示はペインの幅に合わせて
  勝手に伸縮されるだけなので、大きい画像は細部が潰れ、小さい画像は小さいまま
  読めない。倍率を自分で選べること (と、いま何倍で見ているかが分かること) が要る。
  実装は音声プレーヤーと同じく全プレビュー共通の静的ページ `/image.html` で、
  `?src=` で対象を受けるため画像ごとにページを生成しない。
- **拡大はホイールではなくクリック**。プレビューは iframe の中にあり、ホイールを
  奪うと外側のページのスクロールと取り合いになる。クリックなら SSH 越しの
  リモートデスクトップやタッチパッドでも操作が同じになる。クリックと移動の
  区別は「4px 動いたか」「250ms 押し続けたか」で付ける。
- **配信対象の外に出る URL は realpath で弾く**。届く経路が SSH トンネルだけとはいえ、
  symlink をたどって見せるつもりのないファイルを読ませないため。

## 6. 検討した代替案: ターミナル内プレビュー (Kitty graphics)

2026-08-08 に検証した記録。herdr 0.7.5 + WezTerm の組み合わせで、
HTML を headless Chromium で画像化しペイン内に描画する案。
**動くことは実証済みだが、静止画のためテキスト選択・コピーができず不採用**。
リンクも踏めず、依存 (chromium + フォント数百 MB) も重い。

### 検証で分かったこと

前提の設定 (適用済み・無害なので残してある):

- herdr: `experimental.kitty_graphics = true` (`home/herdr.nix`)
- WezTerm: `enable_kitty_graphics = true` (`home/wezterm.nix`、デフォルト false)

herdr 0.7.5 の Kitty graphics 実装の実測:

| 項目 | 結果 |
| --- | --- |
| 生 RGB (`f=24`) | ✅ 通る |
| PNG (`f=100`) | ❌ `EINVAL: unsupported format` |
| チャンク転送 (`m=1`/`m=0`) | ✅ 1720 チャンク 7MB でも通る |
| ピクセルジオメトリ報告 (CSI 14t/16t/18t) | ❌ 無応答 |

- herdr は外側ターミナルの実セルサイズを知らないため、中継時に仮のセルサイズで
  スケールし、素朴に送ると**大きく粗く**表示される (herdr 無しの素の SSH なら綺麗)。
- 回避策は成立する: 外側ターミナルの実セルサイズ (WezTerm で 17x37px) を herdr の外で
  CSI 16t で測って控えておき、**セル数 x 実セルサイズぴったりの解像度でレンダリングして
  `c=`/`r=` を明示**すれば、herdr 内でも等倍で綺麗に表示できる (実証済み)。
- HTML → 画像化はフォントの無いヘッドレス環境だと文字が全部消える。
  `FONTCONFIG_FILE` で nix store のフォント (dejavu / Noto CJK) を指す fonts.conf を
  渡す必要がある。
- ターミナル内ブラウザ [terminal-browser](https://terminal-browser.com/) も検討したが、
  配布バイナリが Apple Silicon macOS のみで Linux では動かず除外。

herdr の実装が成熟して (PNG 対応・ジオメトリ報告・実セルサイズでの中継)
画質問題が解消しても、静止画である制約は残る。再評価するならテキスト選択まで
できる仕組み (terminal-browser の Linux 対応など) が出てきたとき。
