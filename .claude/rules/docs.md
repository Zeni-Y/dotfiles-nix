# このリポジトリのドキュメントを書くとき

**ドキュメントも成果物。** コードを変えたら対応する資料を同じ PR で直す。

## 索引を必ず更新する

`docs/<topic>.md` を追加したら、次の 3 箇所にも行を足す。

1. `docs/README.md` の「ファイル」表
2. `docs/README.md` の「どこを見ればいいか」表 (どんな疑問で辿り着くか)
3. ルート `README.md` 冒頭の補足資料の表

## 文体

- 日本語。常体と敬体は**ファイル内で統一**する。既存ファイルに追記するときはそれに合わせる。
- 見出しは `## 1. ...` のように採番し、長い資料には目次を付ける
  (他の資料からアンカー付きで参照するため。既存の参照を壊すので見出し文言を安易に変えない)。
- 手順は実行できる形で書く。コマンドはコピーして動くものだけを載せる。
- 「なぜそうしたか」と「踏んだエラーの実際のメッセージ」を残す。
  この資料群の価値は、選択肢を比較して**選ばなかった理由**が書いてあることにある。
- 未確認のことは「未確認」と書く。実際に動かして確かめたことは「(確認済み)」と添える。

## 種類ごとの扱い

| ディレクトリ | 扱い |
| --- | --- |
| `docs/` | 恒久的な解説。上の索引ルールが適用される |
| `docs/ref-tips/` | 他 dotfiles からの**採用候補チェックリスト**。ユーザが `- [x]` を付けた項目だけ実装する。勝手に全部入れない |
| `plans/` | 実装前に書いた計画。実装後も履歴として残す。事後に書き換えない |
| `docker/*/README.md` | その環境の使い方とエラー対処。README 本体からリンクする |
